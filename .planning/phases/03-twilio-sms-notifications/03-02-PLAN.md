# Plan 03-02: SMS Dispatches & Alerts Auditor Log

We will build the REST routes for notifications dispatches, construct the dedicated `/dashboard/alerts` logs screen, and update the sidebar layout links and metric widgets.

---

## Proposed Changes

### Component: Notifications API Routes

#### [NEW] [route.ts](file:///d:/New%20folder%20%283%29/src/app/api/notifications/route.ts)
* GET: Read and return historical notification logs from `notifications.json`.
* POST: Receives payload:
  * `{ classId, date, dispatches: Array<{ rollNumber, studentName, parentPhone, message }> }`
  * For each dispatch item:
    * Trigger `sendSmsAlert(parentPhone, message)`.
    * Record log: `{ rollNumber, studentName, parentPhone, message, status: result.mode === 'Twilio' ? 'Sent' : 'Simulator', timestamp: new Date().toISOString() }`.
  * Save all logs atomically inside `notifications.json` database.

### Component: Auditor Logs Screen & Nav links

#### [NEW] [page.tsx](file:///d:/New%20folder%20%283%29/src/app/dashboard/alerts/page.tsx)
* Dedicated logs auditing dashboard displaying a standard table:
  * Headers: Timestamp, Student Name, Parent Contact, Alert Message, Delivery Status badge.
  * Status badges are styled in curated colors (Emerald for `Sent`, Cyan for `Simulator`, Rose for `Failed`).

#### [MODIFY] [DashboardLayout.tsx](file:///d:/New%20folder%20%283%29/src/components/DashboardLayout.tsx)
* Add **"Parent Alerts Log"** in the sidebar navigation menu linking to `/dashboard/alerts` with a custom mail/bell SVG icon.

#### [MODIFY] [page.tsx](file:///d:/New%20folder%20%283%29/src/app/dashboard/page.tsx)
* Fetch historical logs count from `/api/notifications` and display the live **"Parent Alerts logged"** metric dynamically (updating the default blank placeholder of `0` in Wave 2).
