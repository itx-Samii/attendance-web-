# Plan 03-01: Twilio Client Wrapper & Alert Preview Modal

We will integrate the Twilio Node SDK wrapper with environment checks and construct the daily review preview overlay modal on the attendance marking worksheet.

---

## Proposed Changes

### Component: Twilio Client Wrapper

#### [NEW] [twilio.ts](file:///d:/New%20folder%20%283%29/src/lib/twilio.ts)
* Create a clean Twilio client manager:
  * Read `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, and `TWILIO_PHONE_NUMBER` from `process.env`.
  * Define function `sendSmsAlert(to: string, body: string): Promise<{ success: boolean; sid?: string; mode: 'Twilio' | 'Simulator'; error?: string }>`:
    * If credentials exist, initialize the Twilio client and send real SMS alerts.
    * If credentials are missing or invalid, print logs directly to server console and return mode `'Simulator'` with a generated mock SID.

### Component: Front-end worksheets Preview Modal

#### [MODIFY] [page.tsx](file:///d:/New%20folder%20%283%29/src/app/dashboard/attendance/page.tsx)
* Wire an active preview overlay sheet modal:
  * When a teacher clicks "Save Roster Attendance", check if any student has been marked `Absent`.
  * If absentees exist, prevent standard instant saving and pop up the gorgeous glassmorphic **"Review parent alerts"** modal.
  * Render a base template text input allowing educators to custom-adjust institutional template wording dynamically (D-05).
  * Display a list of all drafted SMS cards showing:
    * Student Roll & Name
    * Parent Contact Number
    * Live computed preview of the alert text reflecting custom template changes.
  * Provide an explicit **"Dispatch Parent Alerts"** button inside the modal which commits roster attendance to `/api/attendance` AND posts dispatches to the new notifications trigger endpoint.
